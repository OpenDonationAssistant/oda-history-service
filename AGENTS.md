# AGENTS.md

## What this is

Micronaut **5.1.2** (not Spring Boot) service on **JDK 25** that persists a streamer's
donation/event history. It is event- and command-driven over RabbitMQ and exposes a small
JWT-secured REST API plus a public Donate.Stream webhook.

Entry point: `io.github.opendonationassistant.Application`.

## Build & test

Maven, no wrapper committed (`.mvn/wrapper` is gitignored). JDK 25 is required — the pom
targets release 25.

```bash
mvn test                 # full test suite (JUnit 5)
mvn test -Dtest=AddHistoryItemHandlerTest   # single test class
mvn compile
mvn package
```

**Compilation is strict**: ErrorProne + NullAway run in ERROR mode with JSpecify semantics
(`pom.xml` → `maven-compiler-plugin` compilerArgs). Any nullability violation fails the build.
Every nullable field/param/return must be annotated — use `org.jspecify.annotations.Nullable`
(occasionally `io.micronaut.core.annotation.NonNull`). Assume new code must be null-safe.

Codegen runs during compilation (Micronaut Sourcegen, Serde, Micronaut Data, OpenAPI).
Generated sources land in `target/generated-sources` — never edit them; they are excluded
from NullAway via `-XepExcludedPaths`.

## Architecture

- **Message flow**: `Application.rabbitConfiguration()` declares the exchanges → queues/`type`
  routing. `EventsListener` and `CommandListener` are thin `@RabbitListener`s that delegate to
  `MessageProcessor` (from `oda-commons`), which dispatches on the message `type` header.
  Handler classes extend `AbstractMessageHandler<T>` (also `oda-commons`) and are registered
  by type name = simple class name. To add a handler, create the class and — only if it uses a
  new exchange — wire it in `Application.rabbitConfiguration()`.
- **Domain**: `HistoryItem` (in `history/model`) wraps `HistoryItemData` (the `@MappedEntity`
  record) + `HistoryItemDataRepository`. Concrete per-platform subclasses are selected by
  `HistoryItemRepository.convert()`, a switch on `system:type` (e.g. `"Twitch:follow"`,
  `"Donate.Stream:payment"`). Add new types here and in the switch.
- **Persistence**: Micronaut Data JDBC (`@JdbcRepository(dialect = POSTGRES)`). Query methods on
  `HistoryItemDataRepository` are generated at compile time. `HistoryItemData` is a
  `@Wither` record — its `withXxx()` mutators are generated by Sourcegen, not hand-written.
- **REST**: controllers implement hand-written `*Api` interfaces (`GetHistoryApi`,
  `AddHistoryItemApi`, …) that carry the routes + OpenAPI annotations, and extend
  `BaseController` (oda-commons). Auth via `getOwnerId(auth)` (returns the JWT `sub`; empty →
  return `HttpResponse.unauthorized()`). `DonateStreamWebhook` is `@Secured(IS_ANONYMOUS)`.
- **Dependencies on `oda-commons` / `oda-rabbit-conf` / `oda-test-utils`**
  (`io.github.opendonationassistant`, version `oda.version=0.11.232`) supply the messaging
  framework, `Amount`, `ODALogger`, and `BaseController`. The `AbstractMessageHandler`,
  `MessageProcessor`, and RabbitMQ client plumbing live there, not in this repo.

## Data & migrations

PostgreSQL, schema `history`. Flyway migrations in `src/main/resources/db/migration`
(`V1__…` through `V15__…`, latest = `V15__create-twitch-id-mapping-table.sql`). Add
`V16__…`+ for schema changes; never edit an already-applied migration. `application.yml`
enables `baseline-on-migrate`.

## Conventions

- Records + `@Serdeable` everywhere; money is `io.github.opendonationassistant.commons.Amount`
  (`major`/`minor`/`currency`), not `BigDecimal`.
- Structured logging via `ODALogger` (oda-commons), not SLF4J directly.
- Config lives in `src/main/resources/application*.yml`; default environment is `standalone`
  (forced in `Application`). Required env: `RABBITMQ_HOST`, `JDBC_URL`, `JDBC_USER`,
  `JDBC_PASSWORD`, `JWKS_URI` (Keycloak JWT validation).
- Metrics via Micrometer/Prometheus; counters are defined in `HistoryMetrics`.

## Testing

- Unit tests are plain JUnit 5 + Mockito: hand-instantiate the class under test and mock its
  collaborators — no `@MicronautTest`. Follow `AddHistoryItemHandlerTest` as the pattern.
- Repository tests mock the Micronaut Data interface directly
  (see `TwitchIdMappingRepositoryTest`).
- `micronaut.test.resources.enabled=true` — Micronaut Test Resources can provision a DB for
  integration tests.

## CI / release

Pushes to `master` run the reusable workflow `release_service.yml` from
`OpenDonationAssistant/oda-libraries` (version = GitHub run number), which builds and deploys
the Docker image. `Dockerfile` copies a `target/oda-history-service` native executable produced
by that workflow (not the jar from local `mvn package`). `openapi-config.json` drives generation
of the npm client `@opendonationassistant/oda-history-service-client` (GitHub npm registry).
